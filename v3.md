# CHAPTER 1: INTRODUCTION AND SYSTEM OVERVIEW

### 1.1 Purpose of the User Manual
This User Manual provides complete, step-by-step operating instructions for the **Vinzons Pilot Elementary School – Student Information and Management System (VPES-SIMS)**. It is written for all user groups—prospective applicants, parents/guardians, enrolled learners, faculty advisers, subject teachers, school registrars, and system administrators. Furthermore, this document serves as an official technical and operational reference suitable for inclusion within the academic research manuscript.

### 1.2 System Identification and Institutional Profile
* **System Name:** Vinzons Pilot Elementary School – Student Information and Management System (VPES-SIMS)
* **School Name:** Vinzons Pilot Elementary School (VPES) / Special Science Elementary School (SSES)
* **DepEd School ID:** 112937
* **Division:** Camarines Norte
* **Region:** Region V (Bicol Region)
* **District:** Vinzons District
* **Curriculum Programs:** DepEd K-12 Enhanced Basic Education Curriculum / MATATAG Curriculum, Special Science Elementary School (SSES), and Special Needs Education (SNEd) / Inclusive Education.

### 1.3 System Objectives and Tangible Benefits
VPES-SIMS was designed to eliminate the logistical, clerical, and administrative challenges of traditional pen-and-paper school administration. Key benefits include:
1. **Convenient Remote Admissions:** Parents and guardians can submit the complete DepEd Basic Education Enrollment Form (BEEF) and upload digitized credentials 24/7 without waiting in crowded physical lines.
2. **Orderly Document Verification:** An automated appointment slot booking system prevents on-campus crowding by regulating physical document submission visits.
3. **DepEd-Compliant Academic Management:** Standardized quarterly grading (including composite MAPEH sub-grading) with real-time computation of general averages, passing marks, and honors eligibility.
4. **Automated School Forms Generation:** Direct compilation and export of official DepEd School Forms (SF1, SF2, SF3, SF4, SF5, SF6, SF7, SF8, SF9/Form 138, SF10/Form 137, and SNEd Registry) in standardized Excel and PDF formats.
5. **Data Protection & School Year Gating:** Strict role-based access control, encryption, session protection, and school year transition audits that preserve historical academic records while enforcing compliance with Republic Act No. 10173 (Data Privacy Act of 2012).

### 1.4 Scope and Operational Boundaries
* **Functional Scope:**
  - Online student registration, transferee admissions, balik-aral applications, and continuing student re-enrollment (Kindergarten to Grade 6).
  - Multi-tier document upload, preview, and administrative verification.
  - On-site appointment slot configuration and booking.
  - Section creation, student allocation, and gender-balanced auto-assignment.
  - Faculty management, teaching workload assignment, and timetable scheduling with real-time conflict checking.
  - Teacher grade encoding, MAPEH component averaging, and advisory class management.
  - Export of 10 official DepEd School Forms in PDF and Excel formats.
  - Multi-channel notification pipeline (Hostinger SMTP email queue, Semaphore SMS OTP alerts, and Facebook Graph API synchronization).
* **System Limitations:**
  - VPES is a public elementary school operating under DepEd free basic education; therefore, the system does not include financial billing or payment gateways.
  - The system operates at the school level (SIMS) and feeds verified data to school registrars for official encoding into the national DepEd Learner Information System (LIS).
  - Active internet access is required for real-time authentication, external API calls, and cloud document storage.

### 1.5 System Architecture, RBAC, and Security Framework
VPES-SIMS employs a multi-tiered architecture:
1. **Presentation Layer:** Responsive web interfaces built with HTML5, vanilla JavaScript ES6+, CSS3 modular variables, and interactive UI modals centered on the institutional web portal.
2. **Business Logic Layer:** Object-oriented PHP 8.x REST API endpoints residing in modular directories (`/api/*`).
3. **Data Layer:** MySQL / MariaDB database (`vpes_sims`) utilizing 31 normalized relational tables, strict foreign keys, and transaction integrity.
4. **Security & Authentication Framework:**
   - Single-entry authentication interface via the **Landing Page Integrated Authentication Modal** (`#authModal` / `JS/loginModal.js`).
   - Secure credential verification utilizing Firebase Authentication and the local MySQL `users` database table.
   - 6-digit cryptographic One-Time Password (OTP) phone verification for account activations with anti-spam countdown timers.
   - Dynamic Role-Based Access Control (RBAC) enforcing strict page and API authorization:
     - `admin` (System Administrator / School Registrar)
     - `teacher` (Faculty / Class Adviser / Subject Teacher)
     - `applicant` (Prospective Learner / Parent / Guardian)
     - `student` (Officially Enrolled / Linked Continuing Learner)
   - Immutable audit logging tracking user modifications, logins, approvals, and system configuration updates.

### 3.3 User Sign-In via Email or Phone Number
* **Purpose:** To authenticate existing users and redirect them to their respective role-based portals.
* **Access Path:** Trigger the Auth Modal (`#authModal`) on `index.html`. By default, the modal opens in **Sign-In Mode** (`#modal-loginForm`).

**Figure 2.** Integrated Authentication Modal – User Sign-In Interface  
*[Screenshot Placeholder: Capture #authModal on index.html displaying the "Welcome Back!" header, Email or Phone Number field, Password input with eye unmask toggle, "Sign In to VPES" button, and "Forgot Password?" link]*

#### Step-by-Step Procedure:
1. Click **"Login"** on the landing page header.
2. The **Authentication Modal** appears as a focused overlay.
3. In the **Email or Phone Number** field (`#modal-loginEmail`), enter either:
   - Your registered **Email Address** (e.g., `mariasantos@gmail.com`), or
   - Your registered **11-digit Philippine Mobile Number** (e.g., `09123456789`).
4. In the **Password** field (`#modal-loginPassword`), type your account password.
   - Click the **Eye Icon** (`.auth-password-toggle`) if you need to reveal your typed characters.
5. Click the green button: **"Sign In to VPES"** (`.auth-btn-primary`).
6. The system displays a loading indicator (`#modal-loading`) while validating credentials against Firebase and the local database.

* **Expected Result:** Upon successful authentication, your session is established, your `last_login_at` timestamp is updated, and you are automatically routed to your role dashboard.
* **Important Notes:** If an account has been suspended by the school administrator, sign-in is blocked and an alert displays: *"Your account has been suspended. Please contact support."*

### 3.4 New User Registration and 6-Digit Phone OTP Verification
* **Purpose:** To create a new student or parent account, validated through a mandatory phone-based One-Time Password (OTP) before database registration.
* **Access Path:** Inside the Authentication Modal on `index.html`, click **"Register"** in the top header bar (`#modal-headerRegisterBtn`) or click **"Register"** at the bottom prompt.

**Figure 3.** Integrated Authentication Modal – Account Registration View  
*[Screenshot Placeholder: Capture #authModal switched to registration mode showing inputs for First Name, Middle Name, Last Name, Email, Phone Number, Password, Confirm Password, and reCAPTCHA]*

#### Step-by-Step Procedure (Part A: Submitting Account Details):
1. In the open Authentication Modal, click **"Register"** in the upper-right bar.
2. The modal smoothly expands to the registration view (`#modal-signupForm`).
3. Enter your legal personal name:
   - **First Name** (`#modal-signupFirstName`) — *Required*
   - **Middle Name** (`#modal-signupMiddleName`) — *Optional*
   - **Last Name** (`#modal-signupLastName`) — *Required*
4. Enter your active **Email Address** (`#modal-signupEmail`).
5. Enter your active **Mobile Phone Number** (`#modal-signupPhone`) in the 11-digit Philippine mobile format (`09XXXXXXXXX`).
6. Enter a secure **Password** (minimum 8 characters, containing uppercase, lowercase, and numbers) in `#modal-signupPassword`.
7. Retype the password in **Confirm Password** (`#modal-signupConfirmPassword`).
8. Check the Google **reCAPTCHA** box ("I'm not a robot").
9. Click the green button: **"Create Account"**.

---

#### Step-by-Step Procedure (Part B: 6-Digit Phone OTP Verification):
1. Upon submitting the form, the modal transitions to the **Phone Verification Screen** (`#modal-otpScreen`).
2. The modal displays your masked phone number (e.g., `0912****5678`).
3. Click **"Send 6-Digit OTP Code"** (`#modal-otpSendBtn`).
4. The system dispatches an automated 6-digit verification code to your mobile phone via the Semaphore SMS gateway.
5. Six individual digit boxes (`.otp-digit`) appear on screen, and an anti-spam **60-second countdown timer** begins.
6. Type the 6 numbers received on your phone into the digit boxes. The focus automatically advances to the next box as each number is typed.
7. Click **"Verify Code & Complete Registration"** (`#modal-verifyOtpBtn`).

**Figure 4.** Integrated Authentication Modal – 6-Digit Phone OTP Verification Screen  
*[Screenshot Placeholder: Capture #modal-otpScreen inside #authModal displaying the masked phone number, the 6 sequential OTP input boxes, and the countdown timer]*

* **Expected Result:** The system validates the OTP token, creates the user account in Firebase and MySQL with the default role `applicant`, signs the user into their session, and displays the **Student Type Selection Modal** (`studentTypeModal.js`).
* **Important Notes:** The OTP code expires after 10 minutes. If you do not receive the code within 60 seconds, click **"Resend OTP"** once the timer reaches zero.

### 3.6 Mandatory First-Login Password Change Procedure
* **Purpose:** To secure staff and faculty accounts created with administrative temporary passwords.
* **Access Path:** Triggered automatically upon initial login if `must_change_password = 1`.
* **Prerequisites:** Login using an administrator-issued temporary password.

**Figure 5.** Mandatory First-Login Password Change Modal  
*[Screenshot Placeholder: Capture the firstLoginPasswordModal.js dialog prompting the user to replace their temporary password with a new personal password]*

#### Step-by-Step Procedure:
1. Upon logging in with your temporary password, a modal prompts: *"Temporary Password Detected. You must change your password before proceeding."*
2. Enter your temporary password in the **Current Password** field.
3. Enter your chosen personal password in the **New Password** field.
4. Retype the new password in the **Confirm New Password** field.
5. Click **"Update Password & Continue"**.

* **Expected Result:** The password hash is updated, the `must_change_password` flag is reset to `0`, and you are granted access to your portal.
* **Important Notes:** You cannot navigate away from this screen until a new password complying with security complexity is saved.

### 3.7 Password Recovery (Forgot Password via Email/SMS)
* **Purpose:** To regain access to an account when credentials are forgotten.
* **Access Path:** Inside the Authentication Modal on `index.html`, click **"Forgot Password?"** (`#modal-forgotPasswordLink`).

**Figure 6.** Integrated Authentication Modal – Password Recovery Interface  
*[Screenshot Placeholder: Capture #modal-recoveryForm inside #authModal displaying the email input, "Send Reset Link" button, and "Back to Login" button]*

#### Step-by-Step Procedure:
1. In the login view of the Auth Modal, click the **"Forgot Password?"** link.
2. The modal transitions to the **Reset Password Screen** (`#modal-recoveryForm`).
3. Enter your registered **Email Address** in `#modal-recoveryEmail`.
4. Click **"Send Reset Link"**.

7. To return to the login screen at any time, click **"Back to Login"** (`#modal-backToLoginBtn`).

* **Expected Result:** Your password is reset, and you can immediately sign in through the landing page modal with your new credentials.

---

#### 6.4.1 Interpreting DepEd Quarterly Grades and Passing Status
The grading system adheres strictly to DepEd Order No. 8, s. 2015 (Policy Guidelines on Classroom Assessment for the K to 12 Basic Education Program):
* **Quarterly Columns:** Displays numerical grades for **1st Quarter (Q1)**, **2nd Quarter (Q2)**, **3rd Quarter (Q3)**, and **4th Quarter (Q4)**.
* **Final Rating:** The unweighted arithmetic average of the four quarters, computed automatically:
  $$\text{Final Rating} = \frac{Q_1 + Q_2 + Q_3 + Q_4}{4}$$
* **Passing Standard:**
  - Grades $\ge 75$: Marked with a green badge: **"Passed"**.
  - Grades $< 75$: Marked with a red badge: **"Failed"**.
* **General Average:** Displayed in the summary card at the bottom of the table along with the learner's overall promotional standing (*Promoted to Next Grade Level* or *Retained*).

# CHAPTER 9: Official DepEd School Forms (SF) Reference Guide

### 9.1 Regulatory Framework & DepEd Compliance
The Vinzons Pilot Elementary School – Student Information and Management System (VPES-SIMS) is built in strict adherence to the regulatory standards, grading guidelines, and record-keeping mandates issued by the Department of Education (DepEd) of the Republic of the Philippines. Specifically, the system generates, processes, and archives official DepEd Modified School Forms pursuant to the following key policy issuances:

1. **DepEd Order No. 4, s. 2014:** *Adoption of the Modified School Forms (SFs) for Public Elementary and Secondary Schools Effective End of School Year 2013–2014*. Standardizes School Forms 1 through 7 to minimize clerical burdens on classroom teachers and standardize learner data collection nationwide.
2. **DepEd Order No. 58, s. 2017:** *Adoption of New School Forms for Kindergarten, Senior High School, Alternative Learning System, and Health and Nutrition*. Mandates the standardized integration of School Form 8 (Learner's Basic Health and Nutrition Report) across all public elementary schools.
3. **DepEd Order No. 8, s. 2015:** *Policy Guidelines on Classroom Assessment for the K to 12 Basic Education Program*. Prescribes the grading system, quarterly assessment weighting (Written Works, Performance Tasks, Quarterly Assessment), MAPEH sub-component composite rating calculation, and the reporting format for School Form 9 (Learner Progress Report Card) and School Form 10-ES (Learner's Permanent Academic Record).
4. **DepEd Order No. 34, s. 2022 / Annual Calendar Issuances:** Prescribes standard guidelines for school opening, enrollment procedures, cut-off dates for age requirements (Kindergarten and Grade 1), and mandatory end-of-school-year closing records.
5. **Republic Act No. 10173 (Data Privacy Act of 2012):** Governs the lawful collection, processing, confidentiality, and restricted administrative disclosure of learners' sensitive personal information (demographics, parentage, health status, and academic ratings).

### 9.3 Detailed Specifications per School Form

#### 9.3.1 School Form 1 (SF1): School Register
* **Purpose:** Serves as the primary demographic record of learners in a specific section. It captures the Learner Reference Number (LRN), complete legal name, biological sex, birth date, age as of October 31 of the school year, mother tongue, ethnic group, religious affiliation, complete residential address (house number, street, barangay, municipality, province), parents' legal names, guardian contact details, and socioeconomic classification (e.g., 4Ps household ID).
* **System Automation:** Automatically compiled from verified admission applications (`applications` table) and master student records (`students` table). Data fields strictly conform to DepEd Form 1 standards.

#### 9.3.2 School Form 2 (SF2): Daily Attendance Report of Learners
* **Purpose:** Records daily physical attendance, tardiness, and absences of learners throughout each calendar month. Computes total days present, total days absent, average daily attendance, percentage of attendance for the month, and tracks consecutive absences triggering dropout risk alerts (SARDO – Students at Risk of Dropping Out).
* **System Automation:** The teacher selects the calendar month via the interactive modal in `teacherSchoolForms.html`. The backend aggregates daily entries from `student_attendance`, computes statistical indicators automatically, and formats the output into the standard DepEd monthly attendance grid.

#### 9.3.3 School Form 3 (SF3): Books Issued and Returned
* **Purpose:** Tracks the allocation, issuance date, physical condition upon receipt, return date, and physical condition upon retrieval of government-provided DepEd textbooks and instructional materials for each subject area.
* **System Automation:** Facilitates end-of-year clearance tracking. Unreturned or damaged textbooks are flagged against the student's clearance status prior to promotion processing.

#### 9.3.4 School Form 4 (SF4): Monthly Learner Movement and Attendance
* **Purpose:** Consolidated school-wide monthly administrative report submitted to the DepEd District and Division Offices. Summarizes enrollment changes across all grade levels and sections, including registered learners at the beginning of the month, new enrollees (transferred in), dropouts, transferred out, and end-of-month active enrollment.
* **System Automation:** The Registrar clicks "Generate SF4" in `reports.html`. The system queries section-level data across all active sections simultaneously, eliminating manual statistical tallying errors.

#### 9.3.5 School Form 5 (SF5): Report on Promotion and Level of Proficiency
* **Purpose:** Official end-of-school-year document reflecting each learner's final academic standing: Promoted, Conditional, or Retained. Summarizes general averages and categorizes learners according to DepEd proficiency bands:
  - Did Not Meet Expectations (Below 75)
  - Fairly Satisfactory (75–79)
  - Satisfactory (80–84)
  - Very Satisfactory (85–89)
  - Outstanding (90–100)
* **System Automation:** Pulls certified final grades from the `grades` table. Automatically calculates each student's General Average, assigns the correct descriptive proficiency level, and tallies summary counts by sex and total.

#### 9.3.6 School Form 6 (SF6): Summarized Report on Promotion and Level of Proficiency
* **Purpose:** School-level consolidation of SF5 data across all grade levels (Kindergarten through Grade 6). Formally submitted to the Division Office as the institutional benchmark of academic achievement and cohort survival.
* **System Automation:** Aggregates section-level SF5 records into a unified school-wide statistical table, broken down by grade level and sex.

#### 9.3.7 School Form 7 (SF7): School Personnel Assignment List and Basic Profile
* **Purpose:** Catalogs all nationally funded teaching and non-teaching personnel assigned to Vinzons Pilot Elementary School. Documents employee ID, plantilla position, educational attainment, civil service eligibility, advisory section assignment, subjects taught, weekly teaching load in minutes, and ancillary administrative duties.
* **System Automation:** Synthesizes faculty profiles from `teachers` and `users` tables with actual active weekly teaching assignments from the master timetable builder (`class_schedules` table).

#### 9.3.8 School Form 8 (SF8): Learner's Basic Health and Nutrition Report
* **Purpose:** Documents anthropometric measurements collected during baseline (start of school year) and endline (end of school year) physical assessments. Computes Body Mass Index (BMI), BMI-for-age nutritional status (Severely Wasted, Wasted, Normal, Overweight, Obese), and Height-for-age nutritional status (Severely Stunted, Stunted, Normal, Tall).
* **System Automation:** Automatically computes BMI = $\frac{\text{Weight (kg)}}{\text{Height (m)}^2}$ and maps values to World Health Organization (WHO) / DepEd child growth standards.

#### 9.3.9 School Form 9 (SF9): Learner Progress Report Card
* **Purpose:** The individual periodic report card issued to learners and parents at the conclusion of each quarter. Displays ratings across all learning areas, quarterly and final ratings for MAPEH subcomponents (Music, Arts, Physical Education, Health), observed core DepEd values (*Maka-Diyos, Makatao, Makakalikasan, Makabansa*), and monthly physical attendance.
* **System Automation:** Available for instant digital viewing on the Student Dashboard. Class advisers can generate high-resolution, print-ready bi-fold PDFs individually or download an entire section's cards in a single compressed ZIP archive.

#### 9.3.10 School Form 10-ES (SF10-ES): Learner's Permanent Academic Record
* **Purpose:** Formerly known as Form 137-E. Serves as the cumulative, multi-year transcript of a pupil's entire elementary education from Kindergarten through Grade 6. Required whenever a student transfers to another elementary school or graduates into Junior High School (Grade 7).
* **System Automation:** The Registrar generates SF10-ES from the student's Master Profile in `reports.html`. The system reconstructs the pupil's complete academic progression, historical school years, attendance summaries, and promotional remarks across all enrolled grade levels at VPES.

#### 9.3.11 Institutional Special Needs Education (SNEd) & PWD Registry
* **Purpose:** Specialized institutional inventory of all learners enrolled under the Inclusive / Special Needs Education program. Records clinical diagnoses, learning manifestations, recommended accommodations, assistive technology requirements, and 4Ps coverage.
* **System Automation:** Generated via the SNEd export module in `reports.html`. Enforces strict role-based privacy controls in compliance with the Data Privacy Act.

#### 10.1.1 Issue: SMS One-Time PIN (OTP) Not Received During Registration
* **Symptom:** After entering the 11-digit mobile number and clicking "Send OTP", no SMS arrives within the 60-second countdown window.
* **Root Causes:**
  1. The mobile number was entered in an invalid format (must be exactly 11 digits starting with `09`, e.g., `09171234567`).
  2. The Semaphore SMS API gateway is experiencing carrier-level delivery delays or insufficient API SMS credits.
  3. The user's mobile device has active SMS spam filters, network carrier blocking, or is outside cellular signal range.
* **Step-by-Step Resolution:**
  1. Verify that the mobile number begins with `09` and contains exactly 11 digits.
  2. Wait for the 60-second countdown timer on the verification modal to reach `00:00`.
  3. Click the newly activated **"Resend Code"** link to request a fresh OTP token.
  4. If three consecutive OTP attempts fail, contact the VPES ICT Coordinator or School Registrar to verify the institutional SMS gateway balance or perform a manual account verification.

  4. Click **"Save New Password"**. Upon success, a confirmation notification appears and you will be automatically redirected to your designated dashboard.

### 10.4 Administrative & Server Configuration Troubleshooting

#### 10.4.1 Issue: Database Socket Connection Error / MySQL Port 3306 Conflict
* **Symptom:** Opening the system in a local server environment (XAMPP) produces the error:  
  `SQLSTATE[HY000] [2002] An attempt was made to access a socket in a way forbidden by its access permissions` or `MySQL shutdown unexpectedly`.
* **Root Cause:** A separate background Windows service (e.g., a standalone MySQL 8.0/8.4 enterprise service `MySQL84`) is already occupying network port `3306`, preventing XAMPP's MariaDB instance from binding to the port.

  3. Stop and disable the conflicting background service:

     `Set-Service -Name "MySQL84" -StartupType Disabled`
  4. Open the XAMPP Control Panel and click **Start** next to MySQL. The service will bind cleanly to port `3306`.
  5. Verify that Apache is running and navigate to `http://localhost/vpes-sims/index.html`.

### 10.5 Frequently Asked Questions (FAQ)

#### Q1: Can a parent or guardian enroll more than one child using a single account?
**Answer:** Yes. A parent or guardian can register a single family account using their primary mobile number or email. Once registered, the parent can submit separate admission applications for multiple siblings. Each child will receive their own unique Tracking ID, and once officially enrolled, each child's academic record will be accessible under the parent's linked profile.

#### Q2: What should I do if a student has no middle name?
**Answer:** Under DepEd data standards, if a pupil legally has no middle name (as certified on their PSA Birth Certificate), the applicant or registrar must check the **"No Middle Name"** checkbox on the admission form or type `N/A`. Do not enter a period (`.`) or leave the field blank if validation is enforced.

#### Q3: How is a student's age calculated for Kindergarten admission?
**Answer:** VPES-SIMS adheres strictly to DepEd Kindergarten age cut-off guidelines. The system automatically computes the pupil's exact age as of **October 31** of the incoming school year based on their birth date. If the child does not meet the minimum age requirement of five (5) years old by October 31, the system generates an advisory prompt indicating age eligibility guidelines.

#### Q4: Is an internet connection required to use VPES-SIMS?
**Answer:** VPES-SIMS is architected to operate efficiently in both online and offline environments:
- In a **Local Area Network (LAN)** or local campus deployment (via XAMPP / local server), the entire system operates at high speed without an active internet connection. Internal file uploads, grade entries, timetable scheduling, and PDF generation work seamlessly.
- An internet connection is only required for external web services, including sending SMS OTPs via Semaphore, synchronizing public announcements with the official Facebook Page, or accessing the portal remotely outside the school campus.

#### Q5: Can teachers edit grades after the grading period is closed?
**Answer:** No. Once the administrator closes a quarterly grading window, grade entry cells are permanently locked to preserve data integrity and prevent unauthorized post-deadline tampering. If an encoding error is discovered after closure, the class adviser must submit a formal Grade Correction Request to the School Principal or Registrar, who can temporarily unlock the specific section's grading sheet.

#### Q6: How does the system prevent teacher scheduling conflicts?
**Answer:** The Timetable Builder (`timetable.html`) includes a real-time Conflict Checking Engine. When creating or moving a class period, the engine checks for three simultaneous conditions:
1. **Teacher Clash:** Is the assigned teacher already scheduled to teach another section during this exact time slot?
2. **Room Clash:** Is the designated classroom or laboratory already occupied by another class?
3. **Period Boundary:** Does the scheduled time fall within standard school operating hours and break intervals?  
If a conflict is detected, the system immediately blocks the save action and highlights the conflicting cell in red.

#### Q7: Where are uploaded student documents stored, and are they secure?
**Answer:** Uploaded files (PSA birth certificates, report cards, ID photos) are stored in a dedicated, secure server directory (`/uploads/documents/`) with automated cryptographic filename hashing to prevent file overwrite and direct URL scraping. Access to documents is governed strictly by Session Authentication and Role-Based Access Control (RBAC); only the student's authorized parent, the class adviser, and authorized school registrars have permission to view or download files.

#### Q8: What happens to a student's record after they graduate from Grade 6?
**Answer:** When an administrator processes Grade 6 Graduation in `operationsHub.js`, the pupils' status changes from `Enrolled` to `Graduated`. Their permanent academic history is securely archived in the database. When the student logs into their portal, they are greeted by the Ceremonial Alumni Interface, where they can permanently download their completed School Form 9 (Report Card), Certificate of Graduation, and request an official SF10-ES transcript for Junior High School enrollment.

#### Q9: Can an administrator recover a deleted student record?
**Answer:** VPES-SIMS employs **Soft Deletion** architectures for critical data entities. When a student record is marked as deleted or archived, it is flagged as inactive (`is_archived = 1` or `status = 'archived'`) rather than permanently purged from the MySQL database. This ensures that historical academic transcripts and audit logs remain intact for official DepEd audit and verification purposes.

#### Q10: How do I backup the VPES-SIMS database and document repository?
**Answer:** The School ICT Coordinator can perform full system backups through two methods:
1. **Database Export:** Access phpMyAdmin or use MySQL command line utilities (`mysqldump -u root -p vpes_sims > backup.sql`) to generate a complete SQL snapshot containing all 31 relational tables.
2. **Document Repository Backup:** Copy the entire `vpes-sims/uploads/` directory to an encrypted external storage drive or secure cloud storage facility. It is recommended to perform automated weekly backups during active enrollment and grading periods.

# APPENDIX: Glossary of Terms and Acronyms

* **4Ps:** *Pantawid Pamilyang Pilipino Program*. A human development conditional cash transfer program of the Philippine national government for eligible low-income households.
* **API:** *Application Programming Interface*. A set of protocols, routines, and tools for building software applications and enabling secure data communication between subsystems.
* **BEEF:** *Basic Education Enrollment Form*. The standardized DepEd admission document used to register incoming Kindergarten and transfer elementary pupils.
* **BMI:** *Body Mass Index*. A measure of body fat based on height and weight that applies to adult men and women, adapted for child growth monitoring in DepEd schools.
* **CMS:** *Content Management System*. A software application or portal module used to create, manage, and modify digital content on the public landing page.
* **DepEd:** *Department of Education*. The executive department of the Philippine government responsible for ensuring access to, promoting equity in, and improving the quality of basic education.
* **FPDF / mPDF:** Open-source PHP libraries utilized by VPES-SIMS to compile and stream high-precision, print-ready PDF documents directly to web browsers.
* **ICT:** *Information and Communications Technology*. The infrastructure and components that enable modern computing and digital school management.
* **JSON:** *JavaScript Object Notation*. A lightweight data-interchange format easily readable by humans and parseable by modern web application engines.
* **LAN:** *Local Area Network*. A computer network that interconnects computers within a limited area such as a school campus or computer laboratory.
* **LIS:** *Learner Information System*. The national web-based registry system established by DepEd for collecting and managing learner profiles across all basic education institutions in the Philippines.
* **LRN:** *Learner Reference Number*. A unique, permanent, twelve (12)-digit identification number issued by DepEd to every learner entering the Philippine basic education system.
* **MAPEH:** *Music, Arts, Physical Education, and Health*. A combined learning area in the Philippine elementary curriculum evaluated through four specialized disciplines.
* **MySQL / MariaDB:** The open-source relational database management system (RDBMS) powering the persistent data tier of VPES-SIMS.
* **OTP:** *One-Time PIN (Personal Identification Number)*. A security token sent to a registered mobile phone number to authenticate identity during registration and password resets.
* **PHP:** *Hypertext Preprocessor*. The server-side scripting language driving the backend business logic and RESTful API endpoints of VPES-SIMS.
* **PSA:** *Philippine Statistics Authority*. The central statistical authority of the Philippine government responsible for issuing official Birth Certificates.
* **PSGC:** *Philippine Standard Geographic Code*. The standardized numerical classification of geographic areas in the Philippines (Region, Province, Municipality/City, Barangay).
* **QR Code:** *Quick Response Code*. A two-dimensional matrix barcode utilized on VPES-SIMS appointment slips and student credentials for rapid scanner verification.
* **RA 10173:** *Republic Act No. 10173*, otherwise known as the *Data Privacy Act of 2012*. Philippine legislation protecting personal data and sensitive individual information.
* **RBAC:** *Role-Based Access Control*. A security mechanism that restricts system access and operational privileges based on the authorized role of the authenticated user.
* **REST:** *Representational State Transfer*. An architectural style for software that uses standard HTTP requests to post, read, update, and delete application data.
* **SARDO:** *Students at Risk of Dropping Out*. Learners identified by class advisers as exhibiting high absenteeism or academic difficulties requiring immediate intervention.
* **SF:** *School Form*. The standardized series of administrative records (SF1 through SF10-ES) established by DepEd for basic education institutions.
* **SIMS:** *Student Information and Management System*. An integrated enterprise platform designed to manage student admissions, records, academic grading, and reporting.
* **SMS:** *Short Message Service*. The telecommunications service component that delivers text messages to cellular devices, powered in VPES-SIMS by Semaphore.
* **SNEd:** *Special Needs Education*. An inclusive educational program tailored to provide specialized support and accommodations to learners with disabilities.
* **SPED:** *Special Education*. Educational programs and practices designed for students as addressed under Inclusive and Special Needs frameworks.
* **SSES:** *Special Science Elementary School*. A specialized elementary curriculum emphasizing advanced science, mathematics, and research education.
* **SY:** *School Year*. The official academic calendar year defined by DepEd (e.g., SY 2026–2027).
* **VPES:** *Vinzons Pilot Elementary School*. The primary laboratory and public elementary educational institution located in Vinzons, Camarines Norte, Region V.
* **VPES-SIMS:** The comprehensive web-based Student Information and Management System developed specifically for Vinzons Pilot Elementary School.
* **XAMPP:** A free and open-source cross-platform web server solution stack package consisting of the Apache HTTP Server, MariaDB database, and interpreters for scripts written in PHP.
